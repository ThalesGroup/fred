# Meeting minutes

1. Locate the meeting notes in the request or relevant conversation context. If
   they refer to a document, read it with an available reader. If the notes are
   absent or inaccessible, ask for them before drafting meeting content.
2. Before drafting, read the [minutes template](references/meeting-minutes-template.md).
3. Write in the user's requested language, translating the template labels.
   Preserve the distinction between discussion, proposals and confirmed decisions.
   An invitation, agenda, proposed configuration or forecast is not evidence that
   a meeting happened or that a proposal was approved. If only preparatory material
   is provided, label the output as a preparatory summary and state that no
   confirmed decisions are recorded. Do not turn an offer into a selected supplier
   or a budget estimate into an approved budget.
4. For each action, use only the owner and deadline stated in the notes. Mark
   missing fields as "Not specified", translated into the output language.
   A project milestone is not an action's deadline. Do not infer or invent an
   action date, approval, attendance, author or completion from surrounding plans.
5. Check that each decision and action is supported by the notes. Include useful
   unresolved information without converting it into an invented fact. If a
   requested follow-up action requires an unavailable tool, deliver the minutes
   and explain which action remains incomplete.

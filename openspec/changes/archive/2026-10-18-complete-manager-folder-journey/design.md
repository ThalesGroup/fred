## Context

At `13c660191` the Resources component matches local `origin/swift`; both buttons exist but depend on Python team permissions. Manager has SQL folders with stable UUIDs, immutable placement, space-level read/write, guarded mutations and no folder tuples. Lists are unbounded; deletion rejects children as well as documents. Older Swift plans do not settle this lot.

## Goals / Non-Goals

Preserve the UI while establishing manager as the folder authority. No copied explorer, fake Python permission/tag objects, folder ACL, document workflow, synchronization feature, move operation or legacy-data migration. Documents/ingestion remain a later boundary, not a hidden partial implementation.

## Decisions

- Reuse the folder table, parent constraint and stable identifier path. Renaming changes one label, not descendant identities or grants. Retain existing name rules and depth 15 as an explicit product bound, not an OpenFGA traversal requirement.
- Use owning-space authority for the entire folder tree. A server write decision drives the existing toolbar and menus; every mutation rechecks current authority. Keep organization isolation, personal isolation and the current guarded revocation protocol. No permissions are inferred from a displayed role or copied into SQL.
- Read only the current directory, with bounded pages and deterministic ordering; keep the existing table/pagination controls. In this folder-only lot, pages and totals count matching immediate folders, not KF documents or a fabricated merge of both sources. The existing offset/total presentation can use indexed directory queries; exact totals and deep offsets have a cost proportional to matching siblings, which must be measured and stated. Search and sorting apply to the whole requested directory, not only an accidentally loaded page. Expose the stored creation date for the existing column and name/date ordering; preserve the folder size-sort fallback to name. Document-derived folder size stays unknown using the existing placeholder, never a fabricated zero or KF query. Breadcrumbs resolve bounded ancestors by UUID. Do not download the entire corpus or enumerate documents to navigate folders.
- Specialize root and child predicates before adding indexes. PostgreSQL 15.12 EXPLAIN on 10,000 folders showed the current null-safe parent predicate scanned all 10,000 for one child (214 buffers), while equality/IS NULL used the existing index (3 buffers). This is a plan measurement at concurrency 1, not an application throughput claim.
- Reuse the original Resources presentation and dialogs in place. Change folder bindings and the health/permission dependency that currently masks the page/buttons. Keep document and knowledge-base consumers distinct: a manager folder UUID is never submitted as a KF tag UUID. The document button remains visible in its normal position; the original document panel opens with sending explicitly unavailable; this applies consistently to upload, drag/drop, import and document actions on selected folders. None may initiate a document/tag write, manufacture upload folders or resolve manager IDs through KF. Preserve the unmigrated knowledge-base consumer's behavior.
- Create one root/child, rename without descendant rewrites, and delete a selected folder subtree atomically only when no document references any included folder. Reuse the existing confirmation component with wording that describes folders/subfolders and document refusal. Atomicity is per requested subtree; multiple selected roots retain separate requests, with truthful reporting and refresh if only some succeed. Never walk descendants via one HTTP/FGA request per folder. Presence of documents refuses that whole subtree operation. No ingestion, blob/index deletion or asynchronous deletion framework is added.
- Preserve the existing write lock/fence until focused measurements establish its limit; do not weaken revocation to improve a benchmark. Directory reads cost L(target)+Q(user) Reads and two Checks (read and write); the second decision drives the existing controls without repeating organization resolution. L is placement Reads (0/1/2 for organization/team/project); Q includes every page of the caller's direct roles plus their space placement Reads. Mutations use one write Check, add one exact guard Read and one Write containing two guard operations, with constant stored tuple count. The organization lock covers current checks through SQL commit. UI permission discovery must include its complete request cost, not just its Check. Reads filter roles by exact caller and `object=space:`, placement by exact space and parent/organization relation, and guards by exact scope/version. Checks target the owning space with the pinned model and higher consistency. No folder-specific ListObjects, ListUsers, Expand or BatchCheck is required. User memberships drive Q; folder volume does not. Space hierarchy evaluation inside OpenFGA remains separate from RPC counts. The measured limits and fixture provenance have their authoritative home in arc42 chapter 09.
- Future boundary: manager owns folder identity, containment and authorization; knowledge-flow receives an authorized destination for content processing. It does not create a second classification/ACL authority. This lot adds no such command or document persistence contract.
- Documentation: keep this change to scope, decisions and acceptance. After implementation, reconcile the relevant arc42 chapters with verified responsibilities, invariants, boundaries, failure behavior and measured costs. Remove obsolete descriptions of the replaced UI. Do not turn domain chapters into endpoint/function inventories or describe the future ingestion command as implemented; retain technical evidence in the existing quality chapter and implementation references where needed.

## Risks / Trade-offs

Exact UI reuse must not retain full-tree downloads, per-folder permission/size fan-out or synthetic document successes. Offset totals retain familiar pagination but require measured SQL work at wide levels. Organization-wide write serialization and membership enumeration may dominate concurrent latency; report them explicitly and bring any required lock redesign back for review before implementation. Shared Resources components also serve knowledge-base views, so their unmigrated contracts must remain intact.

## Migration Plan

Fresh PoC data only; preserve current manager folders and grants. Regenerate manager OpenAPI/client and deploy the pair. Add a migration only for a measured schema/index need; never edit applied migrations. No conversion of legacy KF tags or document IDs.

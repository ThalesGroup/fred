## Context

See [proposal.md](proposal.md). The existing UI generator copies an exact canonical allowlist, applies bounded Icon adapters, builds ESM/CSS, and emits closed declarations. The canonical Dialog currently imports FRED translations; Select/Menu import an application OptionModel; Dialog, Select, and Tooltip portal to body. The existing archive contract intentionally excluded these exports until those dependencies and focus behavior were reviewed. The [RFC](../../../docs/swift/FRED-FRONTEND-PACKAGING-RFC.md) requires a consumer-owned themed `.fred-ui` root and local assets; its remaining work stays open.

## Goals / Non-Goals

**Goals:** One maintained component implementation, package-neutral declarations, bounded internal helper graph, behavior-preserving FRED corrections, actual archive/browser evidence, and an unused UI-only alpha coordinate.

**Non-Goals:** More components, new overlay provider, token or SDK changes, application-host/protocol changes, RAGS adoption, publishing, or release workflow redesign.

## Decisions

1. **Canonical source and application boundary.** Extract Dialog's reusable action/focus implementation into a canonical shared primitive and retain a thin FRED wrapper for translated cancel defaults. Public `Dialog` points to the primitive. Select declares a structural generic `SelectOption<T>`; application OptionModel remains assignable without exporting its module. Menu/MenuItem remain internal, with generator adapters narrowing every icon-bearing declaration to the approved MaterialIcon contract. The internal Menu's existing French fallback remains canonical for FRED; an asserted, bounded generator rewrite provides neutral English wording only inside the package when the caller omits `emptyMessage`. This avoids bundling react-i18next or maintaining a package-only component copy.
2. **Portal ownership.** An internal portal helper resolves the nearest originating `.fred-ui` root; Dialog captures the opening focus and a hidden origin anchor so programmatic opening is not misrouted by focus outside the consumer root, while Select and Tooltip use their trigger anchors. A caller-owned Dialog container must remain inside that root. Root-relative portals and reference-counted shared application portal cleanup avoid deleting another component's content and inherit theme. FRED's no-root fallback retains its current body behavior. Dialog's focus containment excludes hidden and negative-tab-index controls. Select consumes Escape only while focused on its open trigger, closes on focus leaving, and stops propagation before Dialog's window handler. Tooltip consumes Escape for its own trigger except when focus belongs to an open Select. No public provider is needed.
3. **Compatibility.** Preserve Dialog's `onConfirm`/`onCancel`, Select's required size and generic onChange, Chip slots/removal, Tooltip interaction/placement, and Checkbox native input contract. Add only public types/labels and accessibility corrections. Existing application aliases and callers are regression-tested rather than exported.
4. **Archive generation.** Extend `UI_COMPONENT_SOURCE_PATHS`, explicit adapter assertions, expected declaration inventory, source graph, and CI exact inputs. Keep root ESM/types and explicit `styles.css`; do not expose internal subpaths. Runtime references resolve only to executable packed modules and TypeScript references only to packed `.d.ts` files; a JavaScript-only path cannot close the declaration graph. Retain CSS structural containment, local-font/hash/license, token variables, React peer/externalization, and all existing token/UI/SDK positive and negative checks.
5. **Release preparation.** Query exact npm versions and repository/workflow history read-only before selecting UI alpha.2. Change only the UI manifest, producer lockfile, and UI changelog; fixture contract metadata derives package expectations from the authoritative member manifest and disposable consumer lock resolution records the tarballs. UI-only validation provisions the reviewed exact token baseline separately, then installs/builds offline from caches. Uncommitted local evidence remains tooling/fixture evidence, not an approved candidate or OIDC publication.

## Risks / Trade-offs

- [Body portal fallback for legacy FRED] → Restrict it to no-root application behavior and assert all neutral package browser overlays stay inside `.fred-ui`.
- [Dialog focus versus a portaled Select menu] → Keep virtual focus on Select's trigger; test nested selection, Escape priority, Tab containment, and focus restoration.
- [Generated bundle/source graph drift] → Require explicit allowlist equality, closed declaration inventory, negative archive mutations, and a clean installed consumer.
- [Unpublished or attempted alpha coordinate] → Halt version selection on inconclusive registry/history evidence; never infer availability from a network failure.

## Migration Plan

1. Record repository/GitHub/npm read-only version evidence and tracking; create the OpenSpec delta.
2. Correct canonical components, wrapper, and internal helpers with focused application tests.
3. Expand producer adapters, archive contracts, actual tarball tests, isolated consumer/types/browser checks, and CI inputs.
4. Synchronize UI-only alpha metadata, lockfiles, changelog and docs; run producer, application, offline, browser, release, OpenSpec, and independent-review gates.
5. Leave uncommitted for review. Publication, Trusted Publisher confirmation, UI-only preparation run, and registry verification are manual later steps. Rollback is source/version review before publication; a published version must never be overwritten.

# Design

## Context

The agreed decisions and exclusions are in the local source specification (`docs/design/STRUCTURED-LOGGING-SPEC.md`, retained locally); motivation is in [proposal.md](proposal.md). The inspected checkout has shared `fred_core.logs.log_setup`, a legacy JSON store representation, Rich console output, captured warnings, and a dedicated non-propagating audit logger. Repeated initialization currently removes root handlers before checking its service marker; dependency warnings/errors are discarded by several non-propagating null handlers. These are concrete foundation integration risks.

Control Plane and Knowledge Flow call the shared setup; hosted agent apps do so in `fred_runtime.app.agent_app`. Knowledge Flow also has `RequestResponseLogger`. Its worker uses separate basic logging, while the Control Plane worker already calls `log_setup`. Runtime `ToolExecution` is the existing shared ReAct/Deep/Graph seam. Ingestion admission persists `PipelineDefinition` inside the existing pending-submission transaction before delivery/retry. Frontend nginx configuration is rendered by `apps/frontend/dockerfiles/docker-entrypoint.sh`.

No shipped OpenSpec capability covers this outcome. The active delegated-execution change does cover authentication and currently requires neutral access records; retain its authentication authority and revise only the superseded logging requirement during slice 2.

## Goals / Non-Goals

**Goals:** One shared output and scope mechanism, attached at existing lifecycle boundaries. Keep every layer independently reviewable and usable when upper layers are absent. Keep one durable logging capability and one issue for the coherent outcome.

**Non-Goals:** Rewriting every log call, moving runtime concerns into the SDK, modifying grant rules, or installing/deploying a log collector. The original specification's exclusions apply unchanged.

## Decisions

1. **Preserve stdlib entrypoints.** Use structlog's stdlib and ContextVar integration in `fred-core`; introduce only shared processors/scope helpers needed by multiple integrations. Snapshot validated bound context in the producing task before a store callback or queue can lose it. Keep `LogEventDTO` timestamp/level/message and structural category behavior through a store adapter. Keep audit formatting independent of generic context. A replacement logger API or route-wide log rewrite adds unnecessary migration work.
2. **Explicit configuration.** Define one typed `app.log_format` choice (`json`/`text`) using shared `fred-pod` ownership and consume it in API/runtime configuration models. Missing values default to text; deployed chart values explicitly choose JSON. Pass stable existing service identity and API/worker role to setup. Replace width-sensitive Rich layout with a renderer that supports intentional multiline text and colors only on eligible output. JSON uses creation-time seconds/nanoseconds and recognized source/HTTP fields. Regenerate schemas from source with existing targets, including root `make generate-chart-schema`.
3. **Own request completion at ASGI lifetime.** A shared ingress middleware observes response start, final body, disconnect, exceptions, and cancellation. It creates fresh request/correlation references and returns `X-Request-ID` and `X-Correlation-ID`, exposing them through existing CORS configuration. Carry a request-owned, explicitly updated context snapshot for completion across task boundaries; do not share a mutable ContextVar dictionary. Disable duplicate Uvicorn access output and replace Knowledge Flow's request/response logger. Log safe route templates and actual status only when sent; failed probes remain visible. Business outcomes are emitted at run/tool/upload completion, separately from HTTP transport success.
4. **Bind where identities are resolved.** Attach user after existing authentication/admission and team/session/exchange/agent IDs in their shared orchestration. Reuse existing runtime/SDK portable traceability fields with actual ingress references instead of generating unrelated bindings. `ToolExecution` owns tool scopes and outcomes across execution models. Nested scope exit restores previous values even on cancellation; explicit clearing removes fields that no longer apply. Detached/retained tasks receive fresh scope ownership or an explicit bounded snapshot, never implicit stale run state. Authorization never consults these diagnostic fields.
5. **One trusted transport envelope.** Use a documented version-1 base64url JSON envelope in `X-Fred-Log-Context`, bounded before decode and after validation. Share encoding, JSON-safe value validation, size/depth/count limits, and reserved-field rules; define exact constants and boundary tests in slice 3. Forward all safe bound fields except reserved fields, without a business-field forwarding allowlist. Attach per request only in existing delegated first-party REST/MCP seams; refuse redirect forwarding to untrusted destinations. Receiver parsing happens after existing principal/grant admission. User and grant-covered run/agent values come from admission; other inherited values survive until locally overridden or explicitly cleared. Invalid diagnostics are dropped with a bounded reason and do not affect a valid business result. Event `extra` cannot override core fields or bound identities.
6. **Persist context at trusted admission.** Add an optional bounded context envelope to existing job payloads, captured before ingestion admission serializes the immutable pending submission. Existing scheduler authorization remains authoritative. Restore context at delivery and activity boundaries with local workflow/run/activity/attempt identities. Reuse Temporal replay-aware logging and pass deterministic data through workflow code; generate fresh correlations outside workflows. Missing envelopes retain existing queued-job behavior. Apply common setup to existing worker entrypoints, including lifecycle workers and any active scheduled-agent entrypoints discovered in current code.
7. **Nginx is the final layer.** Emit escaped JSON access output from the rendered nginx config, with event time, status-derived severity, method and bounded safe routing metadata. Omit raw queries, credentials, sensitive headers and body data. Inventory native error/startup output; retain text where collector parsing is required and document the limitation. No sidecar is needed.

## Risks / Trade-offs

- Cross-task completion may miss business fields → update a request-owned snapshot explicitly and exercise interleaved requests and scope cleanup through real middleware.
- Generic diagnostics become identity-bearing → update observability §6/§7, delegated confinement scenarios and operator notes together; keep audit/metrics rules unchanged.
- Formatter exceptions or sink recursion could disrupt requests → reject unsupported context values early, retain sink guards/bounded buffers, and preserve useful dependency warnings/errors on the console without recursively indexing them.
- Existing jobs and Temporal replay may encounter new payloads → optional fields/defaults, replay-safe workflow handling, and focused legacy-job/retry checks.
- JSON validity does not prove managed-collector timestamp promotion → leave GKE canary verification explicitly pending for rollout, with no deployment in this task.
- Draft status prevents a literal ready-to-merge state → keep all five PRs draft as requested and verify CI, conflict status and unresolved review threads; do not convert or merge them.

## Migration Plan

Use gh-stack rooted on `swift`, creating each next layer only after implementing, checking and reviewing its predecessor: output; request/journeys; delegated propagation; workers; frontend pod. Preserve both untracked `docs/design` files before checkout changes; keep the agreed source spec local unless publication is separately requested.

Each slice has an English migration note and any affected configuration/schema changes. JSON activation is explicit in chart reference values; operators reconcile external parsers and private overlays from published values/notes. Roll back output selection to text if needed. Deploy receivers with optional envelope support before senders; unknown metadata is ignored and old jobs remain executable.

Run focused offline behavior checks at slice boundaries and let CI run broad suites, per the user's instruction. Reuse existing logging, delegated-boundary and scheduler tests; avoid wording/processor-layout assertions and per-route matrices. Perform the repository-required independent correctness and performance reviews when implementation exists. Publish draft PRs assigned to `florian-muller`; fix failures/conflicts/actionable review feedback and verify final head checks and unresolved threads. Record honest rollout limitations, then reconcile/sync/archive this change after all five slices are verified.

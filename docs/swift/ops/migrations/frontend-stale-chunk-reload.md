## Applicability

Existing Fred deployments upgrading to this release. Only the `frontend` image
changes.

## Prerequisites

No additional prerequisites beyond the normal deployment procedure.

## Configuration

No configuration changes are required. The nginx config generated by the
frontend entrypoint now sends:

- `Cache-Control: public, max-age=31536000, immutable` on `/assets/*` (hashed
  bundles), and a real `404` for a missing file there instead of `index.html`;
- `Cache-Control: no-cache` on `index.html`, SPA deep links and other
  root-level files (such as `config.json`).

An ingress or CDN in front of the frontend that overrides `Cache-Control` should
keep `index.html` revalidated, otherwise browsers keep loading a past release.

## Upgrade

Deploy Fred normally. Run a single frontend image version across all frontend
pods once the rollout completes: during a mixed rollout, a page served by one
pod can request chunks that only exist on another.

Tabs opened before this release still run the old code and need one manual
reload; after that, a future deploy is picked up by an automatic reload.

## Validation

`curl -sI https://<fred-host>/assets/does-not-exist.js` returns `404`, and
`curl -sI https://<fred-host>/` returns `Cache-Control: no-cache`.

## Rollback

Use the normal rollback procedure; this change introduces no data migration.

## Limitations

A tab kept open across a deploy reloads once on its next lazy-loaded screen;
unsaved text typed in that tab is lost on that reload.

Partie 3 - recherche par code

Filtrer dans la sandbox avant de répondre

La consigne demande à l'agent d'écrire du Bash ou du Python dans execute_code et de ne renvoyer que des extraits ciblés.

Découvrir

Un glob ou find restreint les noms et les répertoires. Éviter l'inventaire complet de /inputs.

Texte

La consigne propose grep -F pour les termes littéraux et Python pour cinq extraits de 240 caractères au plus.

Variantes

Échapper les termes avant la regex, puis accepter espaces, tirets et underscores; ignorer la casse.

Documents

Inspecter pages, paragraphes ou slides un à un. N'imprimer que les extraits trouvés et leur emplacement.

Tables

Filtrer lignes et colonnes CSV; ouvrir Excel en lecture seule, puis agréger les seules lignes utiles.

Présentation

La trace regroupe le code consécutif; chaque ligne commence par Bash ou Python suivi d'un extrait tronqué et garde son détail. Un autre outil coupe le groupe.

Lecture

Le broker refuse une sélection de runtime absente ou incohérente. Il n'active pas silencieusement le runtime OCI par défaut.

Audit k3d: depuis un vrai Pod gVisor, API Kubernetes, broker, noeud, Internet et metadata sont injoignables; le Pod de contrôle atteint l'API. Racine non inscriptible, UID 65534, aucun token Kubernetes dans le guest.

Kata et le montage CSI restent à tester ensemble sur le cluster cible. Le test réseau gVisor et le smoke CSI k3d ont été réalisés séparément.

Partie 4 - fichiers

Le montage expose une vue, pas le stockage entier

Les fichiers restent dans leurs stores; rclone CSI monte une vue WebDAV en lecture seule.

/inputs/corpus

Bibliothèques documentaires du propriétaire de la conversation, puis permission READ sur chaque document. Pages de 128 candidats sous deux niveaux fixes block-XX.

/inputs/attachments

Originaux des pièces jointes de cette conversation et de cet utilisateur, au plus 32 fichiers. Une nouvelle pièce jointe apparaît après rafraîchissement du cache CSI.

/skills et /work

Skills approuvés issus du même stockage que le catalogue / de Fred, montés en lecture seule. Le script Python d'un skill peut lire /inputs et écrire seulement dans le scratch /work.

Knowledge Flow contrôle le propriétaire réel de la bibliothèque, le type DOCUMENT, les droits du document et la session. La vue échoue fermée sans ReBAC; les appels de code simultanés ouvrent la même vue de façon atomique. Chaque fichier est limité à 20 MiB; une vue à 100 MiB lus et 600 requêtes WebDAV par minute.

Le guest ne reçoit ni credentials du corpus ni accès à d'autres conversations.

Partie 4 - exécution

Une image Python approuvée étend les skills

Le Dockerfile reste une composition légère de bibliothèques, pas un mécanisme d'isolation.

Image documents

Python 3.12 slim, uv, pypdf, python-docx, python-pptx, openpyxl, pandas et duckdb. Digest poussé dans la registry k3d.

Tool minimal

execute_code reçoit seulement language et code. Bash et Python peuvent lire les montages et appeler le script d'un skill; le détail affiche code et résultat.

Différence observée

Small 4 choisit csv standard et corrige un mauvais calcul Excel au second tour. Medium 3.5 choisit pandas et calcule la marge pondérée juste au premier tour.

Sans indice sur les bibliothèques disponibles, les deux modèles ont raté le premier PDF. Après mise à jour de la description de la capability, ils utilisent pypdf et répondent correctement. Les deux choisissent grep pour un gros fichier texte.

Voir les conversations et détails d'outil dans le rapport Playwright.

Partie 4 - preuve et limites

Le cluster recréé teste la chaîne complète

k3d-up, gVisor, SIG Agent Sandbox, rclone CSI, broker, Fred et conversations réelles.

À la demande

WarmPool SIG à zéro. Une sandbox par conversation active, supprimée après 20 minutes sans exécution par défaut; le réglage est administrable.

Lecture prouvée

Corpus texte, DOCX, PDF, PPTX, XLSX, CSV, pièce jointe et skill Python ont produit des réponses vérifiables via le montage.

Isolation sondée

Large 4 n'a pas trouvé de token Kubernetes, de socket Docker ni de pièce jointe d'une autre conversation; les écritures dans /inputs et /skills ont échoué.

Ces tests locaux ne prouvent pas l'isolation de s3ns ou AKS. Avant production, vérifier le CNI NetworkPolicy, RuntimeClass Kata ou gVisor, CSI, limites de processus et admission sous charge sur chaque cluster cible. Le broker unique et son état en mémoire restent à durcir pour la HA.
